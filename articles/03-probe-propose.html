From data to meaning · the first pass

It probes the data — then proposes a draft.

A blank-slate model told to "represent this domain" hallucinates a plausible ontology. This doesn't. Given the warehouse, the agent reads what's actually there — the way a careful analyst would on their first day — and proposes a first draft you can correct.

It probes — the data itself

  • Structure
    tables, columns, types — amounts, factors, dates
  • Cardinality
    5 currencies (closed set) · thousands of product keys (identity)
  • Keys & joins
    the foreign keys — how things relate
  • The actual values
    what a schema hides: "Online" among the countries; duplicate facts in two shapes
→

It proposes — a first ontology

  • ✓
    Concepts — Sales as a measure; Product, Store, Currency, Brand as axes
  • ✓
    Groundings — each concept bound to the columns it found
  • ✓
    Joins — the foreign keys become edges
  • ✓
    Value-sets — currency, brand pulled straight from the data
  • It even raises the oddities as open questions: is "Online" a market or a channel? Should the two shapes ever be added?

A surprising amount of the structure drafts itself. On a warehouse this size the agent can cover much of a first draft in one pass — concepts, groundings, joins, value-sets. Little here is invented; each observation traces back to something the data actually says.
